# Data

## `raw/sales.csv`

Synthetic daily unit sales for three SKUs, generated by
[`scripts/generate_data.py`](../scripts/generate_data.py) with a fixed seed and
committed to the repository. It is synthetic on purpose: notebooks run with no
download step, CI is hermetic and offline, and every agent-authored change sees
byte-identical data.

Regenerate with:

```bash
make data          # or: python scripts/generate_data.py --seed 7
```

Changing the seed changes every metric in `reports/metrics.json` and will trip
the eval gate. Don't do it casually.

### Schema

| column | type | description |
| --- | --- | --- |
| `date` | date (`YYYY-MM-DD`) | Calendar day. Daily frequency, no gaps. |
| `sku` | string | One of `SKU-ALPHA`, `SKU-BRAVO`, `SKU-CHARLIE`. |
| `units` | float | Units sold that day. The forecasting target. Non-negative integers stored as float. |
| `price` | float | List price in USD, discounted 15% on promotional days. |
| `on_promotion` | bool | Whether the SKU was on promotion that day. |

### Shape

- 2022-01-01 to 2024-12-31, 1,096 days per SKU, 3,288 rows total.
- One row per `(sku, date)` pair. The pair is unique.

### Generating process

Each series is a product of interpretable components, so a model that recovers
them is doing real work rather than memorising noise:

- **Base level** per SKU.
- **Weekly seasonality** with a retail shape: quiet Tuesday, busy Saturday.
- **Yearly seasonality** as a sine wave peaking in spring.
- **Linear trend**, positive for `SKU-ALPHA` and `SKU-CHARLIE`, negative for `SKU-BRAVO`.
- **Promotions** in contiguous blocks of 3 to 8 days, roughly one week in six, with a per-SKU demand lift.
- **Holiday lift** from December 15 onwards.
- **Multiplicative noise**, 7% to 14% depending on the SKU.

### Notes for anyone (or anything) modelling this

- `on_promotion` and `price` are known in advance for future dates in this
  dataset, so they're legitimate exogenous regressors. Anything derived from
  `units` is not, and must be lagged. See
  [`src/forecasting/features.py`](../src/forecasting/features.py).
- The default backtest series is `TOTAL`, the sum across all SKUs. Per-SKU
  evaluation is not implemented yet.
